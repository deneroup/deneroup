1Purpose and Scope

This Information Security Policy ("Policy") describes the security framework for DeneroUp, a personal finance application that connects to users' financial institutions via Plaid to provide spending analysis and financial education.

This Policy applies to:

  • All systems, applications, and infrastructure operated by DeneroUp
  • All personnel, contractors, and third-party service providers with access to DeneroUp systems
  • All data processed, stored, or transmitted by DeneroUp including user financial data
  • The DeneroUp mobile application (iOS and Android) and associated backend services
Core Commitment: DeneroUp is committed to implementing reasonable safeguards to protect the confidentiality, integrity, and availability of user data, with particular emphasis on financial data obtained through Plaid's bank connectivity services.

3Access Control and Identity Management

3.1 Principle of Least Privilege

Access to DeneroUp systems and user data is intended to be granted on a least-privilege basis. Personnel are provided access appropriate to their role and operational responsibilities.

3.2 User Authentication

  • All user accounts require email and password authentication
  • Passwords are protected using industry-standard cryptographic methods — plaintext passwords are not stored
  • Minimum password length requirements are enforced at the application level
  • Authentication tokens use secure expiration and access control practices
  • Additional authentication controls may be implemented or modified over time based on security requirements and product development priorities

3.3 Administrative Access

  • Administrative access to backend systems is protected with strong authentication practices including multi-factor authentication where supported
  • API keys and secrets are intended to be stored as environment variables rather than in source code repositories
  • Access to production systems is reviewed periodically and adjusted as operational needs change

3.4 Role-Based Access Control (RBAC)

DeneroUp implements access controls designed to ensure users can access only their own data. Database-level policies are designed to enforce separation between user accounts and prevent unauthorized cross-user data access.

3.5 Personnel and Contractor Security

Personnel and contractors with access to DeneroUp systems may be subject to access reviews, confidentiality obligations, and security awareness requirements commensurate with the sensitivity of the data they access.

3.6 Third-Party Access

Third-party service providers are intended to be granted only the access necessary to perform their contracted services. DeneroUp does not control and cannot guarantee the ongoing security posture of third-party providers.

4Data Protection and Encryption

4.1 Encryption in Transit

  • Data transmitted between the DeneroUp mobile app and backend services is designed to use industry-standard encrypted connections
  • API calls to third-party services are intended to be made over encrypted channels
  • DeneroUp follows practices designed to prevent transmission of sensitive data over unencrypted channels

4.2 Encryption at Rest

  • User data stored in DeneroUp's database infrastructure is protected using encryption at rest provided by the underlying infrastructure provider
  • DeneroUp follows practices designed to limit exposure of sensitive tokens and credentials

4.3 Financial Data Handling

Read-Only Access: DeneroUp is designed with read-only access to financial transaction data via Plaid. DeneroUp is not designed to initiate transfers, payments, or financial transactions. Bank credentials are entered directly through Plaid's secure interface and are not intended to be stored by DeneroUp.

4.4 Data Minimization

DeneroUp aims to collect only the data reasonably necessary to provide its services. Transaction data is used for spending analysis consistent with the Privacy Policy and is not sold to third parties.

5Vulnerability Management

5.1 Dependency and Software Security

  • DeneroUp follows practices designed to identify known vulnerabilities in software dependencies
  • Software components are updated based on risk, severity, operational feasibility, and available resources
  • End-of-life (EOL) software components are identified and addressed based on risk and operational priorities

5.2 Vulnerability Remediation

Remediation priorities are determined based on severity, exploitability, business impact, and operational feasibility. DeneroUp aims to remediate vulnerabilities within commercially reasonable timeframes based on the above factors and applicable legal requirements. No specific remediation timeframe is guaranteed.

5.3 Security Testing

Security assessments and testing may be conducted periodically based on risk, operational needs, and organizational maturity. Code changes are reviewed prior to production deployment where feasible.

6Cybersecurity Threat Awareness

DeneroUp acknowledges that it may be subject to cybersecurity threats including but not limited to:

  • Phishing and social engineering attacks
  • Malware and ransomware
  • Credential stuffing and brute force attacks
  • Denial-of-service attacks
  • Unauthorized access attempts
  • Supply chain attacks targeting third-party software
  • Other evolving and emerging threat vectors
DeneroUp implements safeguards designed to reduce risk from these threats. However, no security system is completely secure and DeneroUp does not represent that it is immune from cyberattacks or security incidents.

7Incident Response

7.1 Incident Classification

  • Critical: Suspected or confirmed unauthorized access to user financial data, active data breach, or complete service outage
  • High: Suspected unauthorized access, significant service degradation, or credential compromise
  • Medium: Minor service disruption, failed security control, or suspicious activity

7.2 Response Objectives

DeneroUp aims to respond to security incidents within commercially reasonable timeframes based on severity, operational constraints, and applicable legal requirements. Response may include detection, containment, investigation, remediation, and post-incident review as appropriate to the circumstances.

Where legally required, DeneroUp aims to notify affected users of confirmed data breaches in accordance with applicable law. No specific notification timeframe beyond what is legally required is guaranteed.

7.3 Responsible Disclosure

Security researchers who identify potential vulnerabilities in DeneroUp's systems are encouraged to report their findings responsibly to customersupport@deneroup.com with the subject line "Security Report." DeneroUp will review reported vulnerabilities and respond as operationally feasible. DeneroUp does not guarantee a specific response time or outcome for externally reported vulnerabilities.

7.4 Security Contact

Security incidents and concerns should be reported to: customersupport@deneroup.com

8Business Continuity and Disaster Recovery

DeneroUp maintains backup and recovery procedures intended to support restoration of critical services following operational disruptions. These procedures are designed to minimize data loss and service downtime, though no specific recovery time or recovery point objective is guaranteed.

DeneroUp's infrastructure providers maintain their own business continuity and disaster recovery programs, the details of which are governed by their respective service agreements and security frameworks.

11Physical and Operational Security

  • DeneroUp operates as a cloud-native application — physical infrastructure security is managed by DeneroUp's infrastructure providers
  • Development workstations are intended to be protected with appropriate security controls
  • Source code is maintained in access-controlled repositories
  • DeneroUp follows practices designed to prevent storage of API keys and secrets in source code repositories

12Regulatory Alignment

DeneroUp's security practices are designed with awareness of applicable regulatory frameworks including:

  • CCPA: Users have rights regarding access, deletion, and opt-out of sale of personal data as described in the Privacy Policy
  • GDPR: Data minimization and user rights are considered for international users
  • COPPA: DeneroUp does not knowingly collect data from users under 13
  • FCRA: DeneroUp is not a consumer reporting agency and does not provide credit reports
  • GLBA: Financial data is handled with safeguards appropriate for a financial application
  • Plaid Developer Policy: DeneroUp works toward compliance with Plaid platform requirements
Regulatory alignment is an ongoing effort. DeneroUp does not represent that it is in full compliance with all applicable regulations at all times.
